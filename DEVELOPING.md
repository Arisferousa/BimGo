# Developing BimGo

How BimGo is built: conventions, the code layout, how each part works, the `.bimgo` format, the live session protocol, known limitations and the roadmap. The user-facing overview and the controls are in [README.md](README.md); every build is listed in [HISTORY.md](HISTORY.md), and each round's handoff and build notes (the full detail behind this page) are in `ai/<yymmdd><letter>_<topic>/`.

## For AI assistants (e.g. Claude)

1. **Read first:** the latest round's handoff and build notes in `ai/` (newest folder last; `0_…` brief or handoff, then numbered build notes), then this file and the README. These docs are the source of truth for what is built; HISTORY.md lists every round and its folder.
2. **Gavin's working copy is the source of truth.** Ask whether it changed (or for a fresh zip with his compile fixes) before editing. Claude usually can't compile here (no .NET SDK, no Revit API): say so in the build notes and list the APIs to verify.
3. **Keep the docs current:** [Open build](#open-build) here holds only the open build's *to verify* entry (once Gavin confirms a build it goes; its notes stay in `ai/`); limitations and roadmap below; a row in HISTORY.md per build; the README's feature list and the **user guide pages in `docs/`** when something user-visible changes (new pictures: a placeholder in `docs/images/` and a row in its README, for Gavin to capture). Write the round's notes in `ai/`. Zip the repo minus `bin/`, `obj/`, `.vs/`, `artifacts/`.
4. **Code style:** readable and robust over clever; XML doc headers; explicit types where clearer; nullable off. **No per-frame allocations** in the app. **No exceptions reach the user:** log with `Utilities.Log_Utils.Write`, show a toast or dialog; errors use `Toast(…, important: true)` (they show even with the UI hidden). Shared helpers go in Core `Utilities/` (e.g. `FileNames.Safe`).
5. **Dependencies: own what differentiates BimGo, rent commodity plumbing.**
   - Own: renderer, shadows, picking, physics, guns, UI look, `.bimgo` format, journal, Revit bridge, live protocol, window / input (`Platform/`, `Native/Win32.cs`, `Native/Wgl.cs`, `Native/XInput.cs`: Windows' own `xinput1_4.dll`, `Native/Joystick.cs`: its joystick API), audio, font atlas, the video writer (`Native/MediaFoundation.cs`: Windows' own encoder).
   - Rent: OpenGL bindings (Silk.NET behind the `Native/Gl.cs` facade; renderer code calls `Gl.Xxx` with `uint` constants; add new calls as facade wrappers).
   - **BimGo.Revit stays package-free** (it loads inside Revit). Revit API references are HintPaths to the installed Revit.
   - Any new package needs Gavin's explicit yes, a permissive licence, a pinned version, a line in [Dependencies](#dependencies) and in `THIRD-PARTY-NOTICES.txt` (how it was procured and its licence). No UI toolkits. Ask before adding folders.
6. **Project boundaries:** **Core** has no Revit, GL or UI code. **App** never references the Revit API. **Revit** is the only project touching the Revit API, only in `Commands/`, `Extraction/`, `Bridge/` and `Live/LiveDispatcher.cs` (Revit thread); `Live/SessionHost.cs` does file IO only. Nothing changes the Revit model except the user's own edits, the family library's temporary transaction (always rolled back), SHOW IN REVIT's "BimGo clash" 3D view, views from BimGo's camera when asked, and comment markers; each in one `BimGo: …` transaction.
7. **Edits go through `IModelSource`** (`LiveSessionSource` or `FileEditSource`) via `GameSession.SubmitEdit`; every accepted edit is recorded in the `EditJournal`.
8. **Compatibility:** `.bimgo` `formatVersion` stays 1 and the live protocol stays 1: only additive, optional fields and entries (a missing field reads as its default). Settings are clamped on load (`LaunchSettings.Sanitise`). Nothing has shipped yet, so there are no migrations of older files or folders: don't add any before v1.
9. **Tests:** `tests/BimGo.Core.Tests` (MSTest 4: `Assert.ThrowsExactly`, not `ThrowsException`). Run after any Core change.
10. **GLSL check without a GPU:** pull the shader strings out of `Rendering/Shaders.cs`, swap `#version 330 core` for `#version 300 es` + precision lines, compile and link in headless WebGL2 (Playwright + the pre-installed Chromium, SwiftShader); give every sampler its own texture unit in a test. Also run Khronos' `glslangValidator` (apt `glslang-tools`) on each stage: it is as strict as Intel's driver (e.g. it rejects a user `float noise3(vec3)`, which clashes with GLSL's deprecated built-in `noiseN`; NVIDIA / AMD accept it). Never name a function `noise1`–`noise4`.
11. **Revit template conventions:** commands in `Commands/Cmds_<Group>.cs` as `Cmd_<Button>`; extensions in `Extensions/TypeName_Ext.cs`; tooltips and icons resolve from the command's base name (`BimGo_Launch`, `BimGo_Export`).
12. **Name clashes:** WPF, WinForms and Revit `DB` / `UI` are global usings in BimGo.Revit; WinForms + System.Drawing are global in BimGo.App. Avoid unqualified `Color`, `Point`, `Plane`, `View`, `Panel`, `CheckBox`, `TextBox`, `TaskDialog` (use the `DB.`, `UI.`, `SD.`, `Wpf.`, `Win.`, `WinForms` aliases). `GameSession` is huge: before adding a type used inside it, check no member has that name.
13. **Keys are actions:** a new key is a new `InputAction` in Core `Scene/InputCatalog.cs` (group, label, kind, default keys; ids are stored in settings, never rename one), read with `input.Pressed / PressedOrRepeated / Down(InputAction.X)`, never raw keys (those are for text boxes only). Every unmodified letter is taken somewhere: list the defaults across all situations before picking one. If an action is live somewhere new, update `InputCatalog.Situations` to match `GameSession.UpdateFrame`. Text naming a key comes from `Hotkeys.Label` (toasts) or a cached `KeyHint` (panels drawn every frame). The Core tests check the defaults for clashes and regenerate the tables in `docs/controls.md`.
14. **Default keys and F1 rows:** changing a default (or adding an action with one) raises `InputCatalog.DEFAULTS_VERSION` and adds rows to `InputCatalog.DefaultsChanges` (checked against the frozen version-0 snapshot by `ControlsTests`); users get a one-time toast and NEW / CHANGED tags. Every `InputSituation` has its F1 rows (most used first, at most 16, only actions live there) and a `SIT_` name; a new situation also goes in `GameSession.CurrentSituation()` (`GameSession.Gamepad.cs`). With a gamepad, A or B with LB / RB held is a chord, so LB / RB + face buttons are safe in the cursor modes.
15. **Big panels use the panel shell** (`Game/GameSession.PanelShell.cs`): `BeginPanel` → body with `ScrollRegion`s (`BeginScroll` / `EndScroll`, draw only `VisibleRows`) → `FooterAction`s → `EndPanel`. Spacing comes from the `UiTheme` tokens, not new magic numbers. Esc / B / ← BACK go one level back through `PanelBack`. Anything drawn inside a scroll region is clipped (`UiBatch.PushClip`) and `Hover` ignores the clipped part.
16. **Docks, HUD columns and gamepad focus:** cursor-mode panels are docks in the right-hand column: `BeginDock` → `BeginDockBody` / `EndDockBody` (no `return` between them without the clip popping) → `EndDock` (returns `DOCK_*`); set the dock's click-blocking rectangle from `DockFrame.Rect`; dialogs run after `EndDock`. The left HUD column is `BuildInfoColumn`. Every `Hover` call is a gamepad focus target: pass `focus: false` for panels, viewports, tracks and canvases; a new slider-like control registers its anchor with `RegisterFocus`; a new tab row calls `TakePadTabStep`.
17. **UI text** uses the font atlas: Latin-1 plus a few extra symbols (`FontAtlas.EXTRA`); check new strings against it. UI text names features, never round or build names.
18. **Revit API notes:** non-user-modifiable shared parameters can't be set; values set on a new adaptive instance may read back empty until `Regenerate()`; `ElementOnPhaseStatus` has no `NotApplicable` (use `None`); `Autodesk.Revit.Exceptions.FileArgumentException` doesn't exist.

## How it works

Each entry names where to look; the round's build notes in `ai/` have the full detail and the reasoning.

### Revit side and sessions

- **Extraction** (Revit thread, `SceneExtractor` + partials). Ticked categories (or the active view), filtered to what stands in the new phase (no view-specific elements, no secondary design options), tessellated, coloured from materials, converted to metres around a scene origin (median element centre, rounded). Each element records ElementId, UniqueId, IFC GUID (the stored `IfcGUID`, else `ExportUtils.GetExportId` compressed), host id, movability + pivot (point-based loadable families that aren't pinned, grouped, nested, in-place or wall-hosted), phase role, extra parameters (Options → Parameters) and its link. Also captured: levels (*Building Story*), rooms (every non-empty instance parameter, in display units: `rooms.json`), grids, lighting, materials, Planting / Entourage instances, provenance (model key = `ProjectInformation.UniqueId`, cloud ids) and the site (true north, base / survey points, the internal → shared transform, latitude / longitude / time zone, the launch view's sun time). A progress window with Cancel; nothing in the model changes.
- **Linked models.** Ticked loaded instances are extracted with the host's categories through their total transform, in the link phase named like the host's; their elements come after the host's (`link` = n), are read-only, and their rooms feed the readout where the host has none.
- **Sessions.** One `GameSession` runs both modes; only the `IModelSource` differs. Live edits are optimistic (applied at once, reverted if Revit refuses): `edit` messages → `LiveDispatcher` → `RevitEditor` (one transaction each, warnings swallowed, named `BimGo: …`). Files: `FileEditSource` accepts at once (removals include hosted inserts).
- **Live sessions.** Go extracts, writes an uncompressed snapshot `.bimgo` into the session folder and starts `BimGo.exe --session <id>` (a running app gets an inbox request and asks before switching models). Revit's 2 s heartbeat keeps `session.json` fresh and flushes `model.changed` counts (BimGo's own `BimGo: …` transactions excluded) → MODEL CHANGED · F5 → re-extract, reload where the player stands. Closing the document sends `session.closing` (the app goes read-only); a stale heartbeat (> 10 s) pauses edits.
- **Journal.** Every accepted edit is appended (both modes): targets by UniqueId (ElementId fallback) or by clone key for clones / placements made in a walkthrough, with pivot, offset, angle, label, author, time and `appliedToRevit`. Opening a file replays it on the untouched geometry; undo removes the last entry and replays the rest; redo is in memory only.
- **Push** (`journal.apply`, `RevitEditor.Push`). The app finds the live session with the file's model key and sends the entries not yet in Revit (plus `knownClones`). Revit applies them in one `TransactionGroup` (one undo), each in its own transaction; moves and clones check the element is still within 5 mm of the recorded pivot (else *conflict*, skipped unless "apply anyway"). Dry run = the same work, rolled back. Requests over 3 MB travel as files.
- **Family library** (`SceneExtractor.Library`, `GameSession.Library`, `PlaceGun`; Options → Geometry, off by default, Go only). Loaded family types of the ticked FFE / services categories (at most *N*, default 200, used types first), each with Revit's preview. Level-based and work-plane / face-based types get geometry from one temporary instance each in a transaction that is **always rolled back**, stored as hidden **template** elements 2 km below the model. The Place gun clones a template; live → `edit` op `place` (`FamilyPlacer` on the level at or below the point, new phase, registered under the clone key); files → journal `place` (replayed by cloning the template). Export .bimgo never includes the library.
- **Revit views from BimGo's camera** (`GameSession.RevitViews`, Core `Live/RevitViews.cs`, `view.make` / `view.request`). NEW makes a perspective 3D view "BimGo NN"; UPDATE sets the active perspective view's camera and crop; the ribbon can ask the app for its camera. One transaction each.
- **Comment markers in Revit** (Core `Live/CommentMarkers.cs`, Revit `Bridge/MarkerSync.cs`, `Cmd_Markers`, app `GameSession.Markers`). One instance of the **BimGo Comment Marker** family (adaptive, one point, three status spheres, type "Default"; embedded in the add-in under `Resources/Families` and written to `%LocalAppData%\BimGo\Families`, compared byte for byte) per comment, its 18 shared parameters set by GUID (`tools/revit/BimGo_SharedParameters.txt`, all user-modifiable; a test checks the GUIDs). Markers are matched by a tag in extensible storage on each instance (schema `BimGoCommentMarker`, field CommentId), BimGo_Id second; the ids BimGo placed live in a DataStorage (schema `BimGoCommentMarkers`), so a marker deleted in Revit stays gone until "put back". `CommentMarkers.Plan` updates differing values, moves points over 1 mm, removes markers of deleted comments (full syncs) and places new ones; values are read back after a `Regenerate()`. One "BimGo: comment markers" transaction only when something differs. Live: `markers.sync` 1.5 s after the last comment change and once at the start. Ribbon → Comment markers: from the model folder's comments (full) or a .bimgo file's (add / update only). Options → Player: live on / off, remove closed, family path.
- **Model folders** (Core `Format/ModelFolders.cs`, Revit `ModelFolderResolver`). `Prepare` creates the folder, writes `model.json` and, with sharing on, takes newer files from beside the model (`PullNewer`, plus comment pictures in `<model>.bimgo-comment-pictures`); with sharing on, writes are mirrored there too. If the folder can't be created, comments fall back to `%LocalAppData%\BimGo\Comments\<title>.bimgo-comments.json`.

### IFC import

Revit LT can't run add-ins, so its way in is IFC (File → Export → IFC); any other IFC works the same. Core `Format/Ifc*.cs`, no packages; the app opens `.ifc` / `.ifczip` from Open, drag-and-drop, the command line and the inbox (`OpenTarget.CanOpen`, `AppShell.ImportIfc`, on a worker with the progress screen) and walks the result as a **new, unsaved file-mode document** (`Path` null, `Kind` `ifc-import`): SAVE asks where to write the `.bimgo` (the IFC's folder offered); the summary is the start notice (`IfcImportSummary.Notice`); the IFC goes in the recent list ("imported when opened").

- **Reading** (`IfcStepFile`): one pass indexes every `#id=TYPE(...)` (type, argument offset; comments and strings respected; `.ifczip` → its first `.ifc`); arguments are parsed on demand and never cached (values: null, `*`, long, double, decoded string (`''`, `\X2\…\X0\`, `\X4\`, `\X\`, `\S\`, raw UTF-8 else Latin-1), enum, ref, typed value, list). Header: schema, originating system (else `IfcApplication`), view definition.
- **Geometry** (`IfcGeometry`, file units, doubles until the scene origin is taken off): the product's "Body" representation (else "Facetation", else the first solid-looking one). Extruded / revolved area solids (profiles: arbitrary with voids, open (a surface), rectangle (rounded / hollow), circle (hollow), ellipse, I / asymmetric I / L / T / U / C / Z, derived / mirrored, composite; curves: polyline, indexed poly curve with arcs, composite, trimmed lines / circles / ellipses (cartesian trims preferred over parameters), circles, B-splines (de Boor, rational)), swept disks, faceted / advanced B-reps (advanced faces on planes only), shells and surface models, triangulated / polygonal face sets (IFC4 ADD2 `PnIndex`), blocks, cylinders, spheres, bounding boxes. Mapped items: each representation map built once in its own coordinates and copied through `MappingTarget ∘ MappingOrigin` (non-uniform / mirrored operators flip the winding). Booleans: union = both operands; difference / intersection by BSP CSG (`IfcCsg`, csg.js's method, iterative, ε = 0.01 mm), half-spaces as a large box on the material side (agreement flag), polygon-bounded half-spaces as that box ∩ the boundary prism; skipped (solid kept) over 20,000 triangles. Openings (`IfcRelVoidsElement`) are subtracted from their host one by one when their boxes overlap. Arcs: chords within 2 mm (12–96 per turn). Winding: generated solids by signed volume; shells and face sets by `IfcMesh.RepairOrientation` (consistent across shared edges, then each part outwards by its volume about its centre).
- **Styles**: `IfcStyledItem` → surface style rendering / shading colour and transparency (alpha as the Revit extractor: 255 − 255 × transparency, 64–255; < 250 is the transparent range); unstyled items take their parent's style, else the element's material's (`IfcMaterialDefinitionRepresentation`, through layer sets, lists, constituents, profiles, else the type's), else a category colour.
- **Elements** (`IfcImporter`): every type whose instances carry a GlobalId, a placement and an `IfcProductDefinitionShape` (so unlisted classes still come in, as generic models), minus spatial elements, openings, annotation, grids, ports, structural analysis items and reinforcement. An aggregate whose parts have geometry is drawn through its parts. Category from the class (`CLASSES`), the predefined type (slab ROOF, covering, member MULLION), the aggregate (curtain wall parts, stair parts, roof slabs), the IFC2X3 type object for generic distribution elements, and proxy names (Revit's RPC trees / shrubs → Planting, other RPC → Entourage, each with an `EntourageSlot` so billboards swap in). ElementId = the IFC instance number; UniqueId = IfcGuid = the GlobalId; name = Revit's "Family:Type:id" without the id (the type name); family / type from `ObjectType`; level from containment (through aggregates, spaces, openings); host = the wall a door / window's opening voids; movable only for FFE / services (pivot = placement origin); phase existing. Parameters: IFC class, Revit ElementId (the `Tag`), predefined type, description, material, then every property set and quantity (own, then the type's), lengths / areas / volumes with the project's unit symbols. Scene: origin = median placement origin rounded to the metre; normals smoothed below 40°; vertices merged per element; opaque then transparent.
- **Model data**: storeys → levels (placement elevation); spaces → rooms (number = Name, name = LongName, outline = boundary edges of the body's bottom faces chained into loops (triangles if that fails), extent = the body's, area = NetFloorArea / GrossFloorArea else the outline's, parameters: Number, Name, Level, Area, then the space's properties; flat spaces (areas) skipped); `IfcGrid` axes → grids; site → latitude / longitude (time zone = longitude / 15) and true north from the model context; provenance key `ifc:<project GlobalId>` so a push never matches a Revit model.

### Engine

- **Drawing.** Batched, frustum-culled `glMultiDrawElements` per category × model; off-screen MSAA; fixed 120 Hz physics; one static BVH for picking and collision; hidden elements by degenerate indices; `DynamicInstance`s (moved originals, clones, placements: the source element's static triangles under a rigid transform, picked and collided through the static BVH with a one-element mask).
- **Performance** (`SceneRenderer.Occlusion`, Core `OcclusionState`, `SceneRenderer.Prepass`, `GpuTimers`). Occlusion culling of the main view: chunk boxes queried with `ANY_SAMPLES_PASSED` after the opaque scene, answers read the next frame without waiting (Off / Auto / On; Auto culls from 250 k triangles in view); a cut or visibility change shows every chunk again until the next answers (`ResetOcclusion`). A depth pre-pass (invariant `SCENE_VS`, then `EQUAL`) lights each pixel once. Light quality (Low / Medium / High: 8 / 16 / 32 shadowed lights) limits the live view; photos and videos use High. Options → Display → Performance details shows GPU ms per stage. A frame rate limit (pause menu → Display: Off / 30 / 45 / 60, default 30, per machine; `GameSession.FrameCap`).
- **Shadows (O).** Cascaded shadow maps with glass transmittance (one glass layer); cascades re-render only when they change. **Ambient occlusion:** half-resolution geometry pre-pass, 12-tap SSAO + depth-aware blur, ambient term only.
- **Artificial lights (K)** (`ArtificialLighting`, `LightShadows`). Glow from Revit self-illumination anywhere, plus lamp / LED / lens / diffuser keyword materials (or a guessed lens) inside Lighting Fixtures; bloom. One light per fixture (lumens / kelvin from its parameters when readable, else 1000 lm / 3500 K). The live view takes the 32 lights that add most (output ÷ distance², at least 1 m; last frame's count 1.5 × so the choice is steady; reach 0.22 × √lm, 3–12 m), each with a cached omnidirectional 6 × 256 px shadow map. Photos, videos and stills (and *All fixtures live*) light every fixture in view: the 32 nearest shadowed, the rest unshadowed, up to 480 (`FarLights` block). Moved / cloned / placed fixtures carry their light; hidden ones go dark.
- **Light profiles** (Core `LightProfiles.cs`, `LightProfileModels.cs`, `LightProfilePolar.cs`; `GameSession.LightProfiles`, `.FixtureProfile`). Extraction finds each fixture type's photometric web file, checks it parses and carries it by content (`ies/<hash>.ies`), with each light's orientation (gamma 0 along the family's −Z, C 0° along its X; the web's tilt turns the aim). Revit spot / hemispherical distributions become generated profiles (`gen:spot:<beam>:<field>`, `gen:hemi`); spherical lights keep BimGo's lobe. `IesData` reads LM-63 type C (TILT factors applied by the aim's angle from straight down); `LightProfile` resamples to 32 gamma × 16 C bytes plus a scale so a profile moves light, never adds it. Five built-ins are generated in code. Choices per fixture type, or per fixture (aim + Ctrl+K: the fixture dock; clones follow their original), in `light-profiles.json`. Renderer: up to 24 profiles in the `LightProfiles` std140 block; a light's colour `.w` < 0 carries slot · octahedral aim · turn. LIGHTS and the dock draw polar candela plots.
- **Materials, Realistic mode** (opt-in at Go / Export; `SceneExtractor.Materials`, `TextureLocator`, `MaterialTextures`). Per material: render colour and colour texture by appearance schema (images found via Revit.ini / registry paths, the Autodesk library if present, the model folder and remembered search folders; never hard-coded; downscaled, JPEG, embedded once), placement (real-world size, offset, angle, tint, fade, invert, blended in linear light like Revit) and per-vertex surface coordinates (world-anchored on planar faces). Missing images fall back to the shading colour, or a CC0 keyword proxy (on by default). Choices per model (Revit: Review textures…; app: TEXTURES; `texture-overrides.json` in the model folder).
- **Reflections** (Realistic; `ReflectivityReader`, `ReflectionProbes`). Strength and roughness from each material's appearance (the only keywords: "mirror" → mirror, see-through "water" → water); shine rounds to 25 % tiers and reflects at the threshold (Some = 50 %+, All = 25 %+); metals tint; glass uses Revit's reflectivity (× 2.5, 10–50 %). **Probes:** one per room holding a reflective surface (a grid every ~8 m in rooms over 12 m) plus fallbacks outside rooms; six faces each in one mipmapped RGBA8 array (128 px, HQ 256; ≤ 64 probes); baked progressively (2 faces a frame, nearest first) and re-baked after the sun, lights, colour mode or model change. A plan grid (0.5 m cells × bands) names up to two probes per cell; each room claims its cells, blends cross only open boundaries (a short ray crosses no wall), and the shader looks the cell up just off the surface along its viewer-facing normal, so rooms don't leak into each other.
- **Sharp reflections in stills** (`SceneRenderer.PlanarReflections`, `.ScreenReflections`, Core `ReflectivePlanes`; photos, videos, batch stills, 360s and photo mode's preview; the live view keeps the probes). **Planar:** glass and mirror-like triangles grouped by plane at load; each still draws the best 2 / 4 / 8 planes in view from the mirrored camera into a 2D-array layer (the plane as an extra clip plane), read by glass and mirror fragments on that plane. **Screen-space:** up-facing flat surfaces march the half-resolution pre-pass and read the previous frame's colour; misses keep the probes / sky. Each still is first drawn small from its own camera for the history. Debug → SSR colours them.
- **Sky, water and grass.** Procedural clouds, sun size and glare (sun panel → SKY; reflected by glass and probes). Water: keyword or asset water ripples (strength, speed, wave size), colour and reflection strength. **Grass blades** (Realistic) on upward grass-keyword surfaces: a top-down `GrassField` (built on a worker; follows hidden / moved elements once a change settles) drives instanced clumps around the eye.
- **Night sky** (Core `LunarPosition`, `SunLighting`, `SkyLook`, `SKY_FS`). The moon's place (low-precision elements + main perturbations + parallax, ≈ ¼°) and phase; below −1° sun altitude the moon is the light (0.10 × the sun at full × phase × the slider). Stars: hashed cells on the celestial sphere turned by sidereal time, latitude and true north; a Milky Way band. Probes draw no stars.
- **Weather** (Core `CoverMap`, `LightningStorm`; `SceneRenderer.Weather`, `GameSession.Weather`, `Audio/WeatherSound`). A cover map (the highest visible static or moved surface per 0.5 m cell, R32F) decides what is open to the sky. Rain / snow: one instanced draw of streaks or flakes in a world-anchored repeating pattern round the eye, discarded under cover; wet surfaces darken and gain a sheen and puddles; snow covers by drift noise. Lightning strikes come from the weather clock alone (so videos match), with a sky patch, a zigzag bolt and a scene flash (Reduce flashing softens it); lens drops refract a copy of the frame; rain and thunder play on their own waveOut stream.
- **Entourage billboards** (Core `EntourageArt`, `EntourageShapes`, `EntourageSlots`, `Format/EntourageModels.cs`; `SceneRenderer.Billboards`, `GameSession.Entourage`, `EntourageStore`, `PlaceGun`). Built-ins (trees, shrubs, hedge, grass, people, cars) drawn in code at start on a worker, seeded so every machine draws the same; the user's PNG / JPEG cut-outs (background keyed out when the corners agree). Every picture is a 512 px layer of one texture array. Drawn as instanced quads facing the eye, alpha-tested, lit like foliage; in each shadow cascade they face the sun. **Revit Planting / Entourage** instances are swapped for billboards: instance rule, else type rule, else (on by default) **AutoType** by name and size, else the Revit element; the elements stood in for are hidden like a profile's hidden rows. Not in AO, probes, light shadows or the minimap; no collision. Stored in `entourage.json` (+ pictures).

### Clash detection

Core `Clashes/`, App `Game/Clashes/`. **Dormant** until Y or CLASHES (a file's `clashes.json` is carried through saves untouched); then it loads `clashes.json` or seeds two starter tests. **Search sets:** rules on category, family, type, level, phase, model and extracted parameters with operators (is, is one of, contains, number ranges; "not" operators take elements out), in rule groups nested to any depth. **Tests:** A × B or A × itself, hard (deeper than the tolerance) or clearance, on the geometry as walked; sweep and prune over boxes, then triangles in parallel (Möller tri–tri), ≤ 10,000 clashes per test. **Across runs** a clash keeps its id by test + element pair (found again → active, missing → resolved; review fields stay). **Clash mode** (Y): a docked list, flying, a section box round the current clash, ghost / wireframe / real / hidden, statuses, R shows the pair in Revit. **Groups** (`ClashGroup.ClashIds` is the truth; auto by element / level / category / grid; by box, pick points, cluster). Clashes and groups become comments (and so BCF). **Reports:** self-contained HTML and Navisworks-style XML; BimGo report JSON merges another copy's statuses. Tests and sets export / import with link / level reconciliation by name.

### Input, UI and the app shell

- **Input** (Core `InputCatalog`, `KeyChord`, `KeyMap`; App `Platform/Hotkeys`, `InputState`, `GameSession.Controls`). Every key is an `InputAction` (group, kind press / repeat / hold, up to three default chords + a gamepad binding). **Situations** list what can fire together, mirroring `GameSession.UpdateFrame`; two actions clash only when a situation holds both. `KeyMap` answers `Pressed` / `PressedOrRepeated` / `Down` / `Axis` without allocating and applies the modifier rule (extra modifiers don't stop a binding unless a live binding on the same key needs them). Settings keep only the changes (`KeyBindings`, `PadBindings`); keymap files export / import every action.
- **Gamepad** (`Native/XInput.cs`, `Native/Joystick.cs`, `Platform/Gamepad.cs`, Core `GenericPadMap`, `GameSession.Gamepad`, `.PadMapping`, `.GunWheel`). XInput read once a frame (else one generic joystick through a button map set up with MAP BUTTONS…), as 24 gamepad codes with edges, auto-repeat, a radial dead zone and analog axes; LB / RB are modifiers. In menus and the free-cursor editors the look stick drives the Windows cursor; the D-pad moves a focus ring (`GameSession.PadFocus`). The gun wheel (MMB / RS click) picks guns.
- **UI.** One `UiBatch` per frame (font atlas, clipped scroll regions), the panel shell for big panels and docks for the cursor modes (see the conventions above); the HUD's left column (status, coordinates, legends, F1) and right column (minimap, gun panel or dock).
- **App shell** (`Program`, `Shell/`). One window alternates between the home screen (live sessions, Open, recent files with thumbnails saved in each `.bimgo`, drag-and-drop) and walkthroughs. Single instance: a second launch drops a request in `%LocalAppData%\BimGo\App\inbox\` (only existing `.bimgo` paths and valid session ids are accepted) and brings the window forward. The installed copy keeps `.bimgo` registered to itself.
- **Install and first run** (`installer/`, `build/publish.ps1`, `GameSession.Welcome`, `LaunchSettings.SafeStart`, Core `Live/VersionCheck`). The setup installs the self-contained app and the bundle (Revit 2025 / 2026 / 2027 components in `PackageContents.xml`, each year loading only its own), removes developer copies under `Revit\Addins\<year>\`, refuses to run while Revit or BimGo is open, runs `--register` / `--unregister`, and on uninstall asks whether to remove settings and logs (per-model data always stays). The first walkthrough on a PC shows a welcome card (keys, START WALKING, ONLINE GUIDE → `docs/`; settings `WelcomeShown`). Holding Shift at start (or `--safe`) is a **safe start**: `LaunchSettings.LoadOrDefault` gives defaults with the Basic profile and `Save` does nothing for that process. **Version check:** Go compares the add-in's version with BimGo.exe's file version and asks before going on; the app compares the session's `AddinVersion` with its own and shows an important toast (`VersionCheck.SameRelease` compares major.minor.patch).

## The live session protocol (version 1)

| Direction | Type | Payload |
|---|---|---|
| app → Revit | `hello` / `detach` | pid, version / none |
| Revit → app | `hello.ack` | title, Revit version, new and existing phase |
| app → Revit | `edit` | `EditRequest`: ticket, op (`phaseDemolish` / `delete` / `transform` / `copy` / `place`), ElementId or clone key, `newCloneKey`, pivot, translation, angle, label; `place` adds `typeUniqueId`, `typeId` |
| Revit → app | `edit.result` | ticket, success, message, affected ids, new id, clone key |
| app → Revit | `extract.request` | reason |
| Revit → app | `extract.ready` / `extract.failed` | snapshot path, number, counts, seconds / message |
| app → Revit | `select.elements` | ElementIds; optional `linked[]` (link instance + element); optional `hosts[]` (host elements joining a linked selection) and `clashView` (SHOW IN REVIT: `name`, `sectionBox`, min / max, eye, direction; Revit internal metres) |
| Revit → app | `select.result` · `model.changed` · `session.closing` | success / counts / reason |
| app → Revit | `journal.apply` | dry run, tolerance, apply conflicts, model key, phase names, file name, known clones, entries (or `payloadPath`) |
| Revit → app | `journal.result` | per entry: `applied` / `skipped` / `conflict` / `failed` / `alreadyApplied`, message, new id; totals, undo label |
| app → Revit | `view.make` | `action` (`create` / `update`), `askedInRevit`, eye, forward, up (Revit internal metres), horizontal FOV (degrees), aspect |
| Revit → app | `view.result` · `view.request` | success + message (shown as a toast) · the ribbon asks for the camera (`action`); the app answers with `view.make`. `hello.ack` gains `revitViews: true` |
| app → Revit | `markers.sync` | `markers[]` (id, x / y / z Revit internal metres, title, comment, status, priority, author, assignedTo, created, updated, level, element, replies, picture, isOpen / isInProgress / isClosed / isHighPriority), `full`, `replaceAll` |
| Revit → app | `markers.result` | success, message, placed / updated / moved / removed / deletedInRevit / skipped; `hello.ack` gains `commentMarkers: true` |

Envelope: `protocol`, `id`, `seq`, `sessionId`, `type`, `replyTo`, `sentUtc`, `payload`; files `<utc>-<seq>-<type>.json` (`.tmp` then rename), read by a watcher + 1 s poll, validated (session, protocol, 4 MB cap), de-duplicated and deleted. Messages and ops are additive: an older add-in ignores `journal.apply` and can't read `place` (the app times out with a hint to update); it ignores `view.make` too (the app sees no `revitViews` in `hello.ack` and says the add-in needs updating); without `commentMarkers` in `hello.ack` the app sends no `markers.sync`.

## Known limitations
- Undo / redo are file-only (live: undo in Revit, then F5). Refresh is a full re-extract. Show in Revit needs the session's model to be Revit's active document. One window walks one model.
- Linked models: top-level instances only; phases matched by name; read-only; their levels don't join PgUp / PgDn.
- Demolish removes hosted elements with their host. Project coordinates ignore the base point's own angle to true north.
- Push: moves / clones need a location point; no duplicate guard beyond the journal flag (if a push times out, check Revit before pushing again).
- Active view only: plans / sections follow their view range; temporary hide / isolate may not be honoured.
- Rendering: one glass layer for shadows; no cascade blending; light shadows 256 px per face, glass doesn't cast them; AO is screen-space; Realistic's bump comes from a height image (no normal maps) and cutouts are an alpha test (no soft edges), both only for matched materials (materials round); texture origins are world-anchored. Probes are static captures (box-projected; a room without reflective surfaces reflects the sky). Clouds don't light or shade.
- Light quality: Medium by default in the live view (16 shadowed lights, 8 soft); lights crossing the 8 / 16 line switch shadows; photos and videos always High.
- Occlusion culling (Auto by default: culls while ≥ 250 k triangles are in view): the main view only; a chunk coming into sight from behind a wall shows a frame late; moved / cloned elements and billboards aren't culled.
- Light profiles: per fixture type, or per fixture (a clone follows its original, placed library copies use their type's); spherical Revit lights keep BimGo's lobe; a spot's tilt is read like a web's (90° = down); IES tilt factors use the aim's angle from straight down for every lamp geometry; type A / B photometry is refused; 16 C × 32 gamma steps (very narrow beams soften); the live view ranks lights by output ÷ distance², not by what's on screen.
- Billboards: Revit swaps use each instance's box (a rotated family's width is its larger plan size) and the type's picture; links' instances are matched by their link instance; the active view only records what that view shows. They always face the camera (a car shows its side from every way); no collision, AO, reflections in probes, light shadows or minimap; no undo for planting / removing; imported pictures are fitted into 512 px layers; model-folder pictures aren't mirrored beside the model when sharing is on.
- Grass: not in AO or the minimap; no steep banks (> ~70°); under a roof garden over a lawn the top one wins.
- Weather: the cover map is one height per ~0.5 m cell (bigger on large sites), so rain can stop up to a cell short of an edge and a slatted pergola counts as a roof; it follows hidden / moved elements only once a change settles; snow buries all grass blades alike (even under a roof); probes show wet / snowy surfaces as they were at the last bake. Lightning only while it rains, never in reflections; videos have no thunder (no sound in videos); snow has no sound.
- Family library: level-based and work-plane / face-based types only (wall-hosted listed, not placeable; work-plane types go on the level); ticked FFE / services categories only; Export never includes it.
- Photo: no stereo / VR; very large stills drop MSAA; faint seams possible where 360 views meet; grid bubbles / labels (2D) never appear in photos.
- Section: one free plane (BCF keeps the first of several); caps need closed solids; transparent geometry isn't capped; the minimap shows the uncut plan. Profile-coloured caps colour the surface seen through the cut (a solid inside another takes the nearest one's colour).
- Daylight / sun hours: indicators only; one glass transmittance (0.7); IRC one value per room; clear sky only; sun hours are geometric (no diffuse sky or reflections; a cell is lit or not). Saved studies live in the model folder, not the `.bimgo`.
- BCF: plain 2.1 out (no markup, coloured / hidden components or extensions); first viewpoint only on import; FOV clamped to 45–60°. Shared comment pictures (sharing on) are copied, never deleted, beside the model (`<model>.bimgo-comment-pictures`).
- Video: no sound; probes aren't re-baked while recording a tour or path (a time-lapse re-bakes them as it plays, a step behind the light); synchronous rendering. Time-lapse: one fixed view (no camera path yet), one date (an overnight range runs into the next); the clouds' fast drift is a look. Batch stills: one PHOTO setting for all; a typed date uses the view's daylight-saving tick (a place with a zone decides itself); no contact sheet. Location: city reference points; the zone's current standard offset for every date.
- Tour: a glide flies straight through walls (no path finding); the sun blend switches shadows on / off half way when one stop has them off.
- Camera paths: paths fly through walls (the editor marks them red: visible static geometry only, not moved / cloned elements); undo lasts the session; a speed change at a key that doesn't ease is a step; speeds and look-ahead are metric; keys keep no FOV; an own-view or look-at key blends over half of each neighbouring segment (no blend length yet); a smooth tour's single stop plays as a fade; key photos and the batch use the window's aspect (stills) and the PHOTO settings of the moment; the sun blend's clock time doesn't wrap through midnight.
- Review tools: areas are planar; clearance is vertical (floors / ceilings) or level across (walls), not along a sloped normal; deleting all measurements is X twice. Markup is burned in. Units: snaps, eye-height steps and sun-hours grids stay metric; CSV in metres.
- Clash detection: hard depth is an estimate; an element wholly inside another isn't reported; closed solids assumed; no MEP connectivity; a test keeps its first 10,000 clashes; the wireframe view shows triangle edges; clash pictures have no AO or glow; row pictures live for the session; clash comments' text is set when made; SHOW IN REVIT adds one view ("BimGo clash").
- Colour profiles: by-set profiles follow clash detection's sets; quantile ranges merge repeated edges (fewer ranges than asked); a value on a break goes in the lower range.
- Key bindings: three keys per action; text boxes keep their own keys; the menu / dock gamepad navigation (D-pad focus, LB / RB tabs, A / B) is fixed; some actions stay keyboard-only on purpose (set home, find room, save / undo, section plane / clear, sun ±1 min, markup tools). Gamepad: XInput or one mapped generic controller per machine; no vibration or on-screen keyboard.
- Silk.NET may bring a newer `System.Text.Json.dll` beside `BimGo.exe` (behaviour identical).
- Install: not code-signed for 1.0 (SmartScreen warns on the download; Revit asks once whether to load an add-in from an unverified publisher). Per user only (no machine-wide install). A Debug build writes a `PackageContents.xml` listing all three Revit years, so a year never built on that PC may report a missing add-in; build it once or delete its entry. The welcome card and docs links point at GitHub (`main`), so offline PCs get no guide.
- IFC import: read-only in effect (edits stay in the saved .bimgo's journal; nothing pushes into an IFC or Revit LT); advanced B-reps only on planar faces (IFC4 Design Transfer View curves left out), no NURBS surfaces, tapered extrusions use their start profile; no textures or reflections from IFC materials (colours and transparency only); booleans skipped over 20,000 triangles; reinforcement, annotation, structural analysis items not imported; spaces need a 3D body to become rooms; time zone guessed from the longitude; IfcMapConversion (survey coordinates) not read; one `.ifc` per model (no federation: import each file separately).
- Site photos: JPEG only (HEIC needs converting); GPS from phones is a few metres off, so photos placed from it can land on a roof or in a wall (pin those by hand); the heading correction is one offset for all photos; altitude isn't used (photos stand 1.6 m above the first floor below them); thumbnails show for the nearest 40; photos in a live model folder aren't mirrored beside the model when sharing is on; all pictures are held in memory (about 0.4 MB each); updating from IFC drops the walkthrough's edits and textures picked for the old geometry, and assumes the new export keeps the project's coordinates; showing only one group isn't saved.
- Materials for IFC models: the image is planar-mapped (plan on floors and roofs, along and up on walls; curved surfaces stretch); see-through stays as the IFC sets it (no opacity control); cutouts don't cut artificial lights' shadows or the section caps; the eyedropper on a moved copy picks the element's most used material; the Autodesk library is found in its standard places and registry keys only.
- Simple viewer: no ViewCube or orthographic views; orbiting goes through walls and under the ground (no collision); the gamepad only walks and looks there; the toolbar isn't rebindable (mouse buttons are fixed); a viewer file stays one when saved from the full walkthrough (save a normal copy from your own working file).
- Kiosk mode locks BimGo, not Windows (the Windows key, Alt+Tab, Ctrl+Alt+Del and Task Manager still work; use a Windows kiosk account for a locked public PC); the shortcut stores the exe's path (remake it after reinstalling elsewhere); taking over the tour at a crouched stop pops up to standing height.

## Roadmap

- **Done:** v1–v7 and 1.0 (live sessions, files, push, sun, links), rendering (SSAO, lights, materials, reflections, probes, sharp reflections in stills, IES profiles), review tools (comments as issues, BCF, section box, measure, markup, rooms, colour profiles, grids, clash detection), media (photo, tours, camera paths, video, time-lapse, batch stills, entourage), weather and night sky, input (rebinding, gamepads), performance (occlusion culling, depth pre-pass, light quality), the Revit round-trip (room data overlay, comment markers), kiosk mode, a pre-installer cleanup and IFC import (Revit LT).
- **Next:** Z-E installer and first run (open); then a **beta** on a few other PCs (integrated graphics, older drivers, high-DPI laptops, colleagues' Revit), real screenshots and GIFs in `docs/images/`, and the **1.0 release** (`docs/releasing.md`).
- **Later:** live sharp mirrors ("mirror" materials only, one plane, off by default; the full live retry was judged not worth it before v1: see the X-C1 notes); OpenXR VR; review tools (find element search, accessibility checks, travel-distance tape, profile schedule CSV); IFC import part 2 (curved advanced B-reps, IfcMapConversion, several IFC files as links); entourage (wind sway, fixed-heading cars, undo for planting, billboards in probe captures); scale part 3 (small-detail culling, simplified meshes) if big models need it.
- **After v1:** async sharing through cloud folders (each person writes only their own small files, merged on read; a poll with "Sam added 2 comments" toasts; care for cloud-only placeholders). Shelved until after v1 because it changes the single-player feel.
- **Parked:** real-time multiplayer (it would make BimGo a hosted service; lighter steps first if wanted: one BimGo hosting on the office network, a spectator mode).
